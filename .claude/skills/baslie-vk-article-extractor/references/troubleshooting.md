# Troubleshooting baslie-vk-article-extractor

Подробный разбор частых проблем. SKILL.md ссылается сюда — читай только если
встретил конкретную ошибку.

---

## VK показывает форму логина / редирект на login

**Симптомы:**
- `summary.json.images_total == 0` или подозрительно мало;
- в `article.md` нет ожидаемого контента, зато есть слова «Войдите», «Login», «UnauthAction»;
- `status_code` 200, но контент пустой / `cleaned_html` маленький;
- в логе скилла предупреждение «Среди куков нет remixsid».

**Причина:** в живом Chrome, к которому подключился скилл, не залогинен VK,
или сессия инвалидирована (Chrome давно не открывался, VK выкинул).

**Что делать:**
1. Проверить, что Chrome слушает CDP:
   ```bash
   curl http://localhost:9222/json/version
   ```
   Если ответа нет — см. раздел «Скрипт падает: CDP endpoint недоступен».
2. В этом Chrome открыть `https://vk.com/feed`. Если форма входа — войти руками
   (логин + пароль + 2FA, как обычно). После успешного входа лента должна
   подгрузиться без перезагрузки.
3. Запустить скрипт снова — он заберёт обновлённые куки автоматически.

Скилл сам подсказывает в логе, если среди куков нет `remixsid` — это
сильный сигнал «VK не залогинен в этом Chrome».

## `images_downloaded < images_total`

**Симптомы:** часть картинок не скачались, в `images.json` у них поля `error` или `status: 403/404`.

**Причины:**
- VK CDN иногда требует `Referer: https://vk.com/` (мы его шлём, но иногда сервер CDN всё равно отвечает 403, особенно для горячих/новых фото);
- ссылка с временной подписью истекла между моментом, когда crawl4ai снял HTML, и моментом, когда httpx начал её скачивать (редко, но бывает).

**Что делать:**
- если потеряно 1–3 фото из 30 — допустимо, остальной контент в порядке;
- если потеряно >50% — открыть `https://vk.com/feed` в живом Chrome (с дебаг-портом), убедиться, что VK залогинен, и запустить скрипт ещё раз;
- стойко падает на конкретный URL — открыть его в браузере вручную и проверить, не приватный ли он.

## `videos_total == 0`, а на странице видео есть

**Причина:** VK Video и YouTube embed'ы обычно идут через `<iframe src="vk.com/video_ext.php?...">` или `youtube.com/embed/...`. Crawl4AI с `process_iframes=True` старается зайти внутрь, но не всегда подхватывает источник в `result.media.videos`.

**Что делать:**
- посмотреть в `links.json → external` — там может быть прямой URL ролика;
- посмотреть в `article.html` (поиск по `iframe`) — `src` iframe-а виден напрямую;
- если нужно стабильно собирать видео — это известное ограничение, может быть доработано позже (пока скилл просто фиксирует факт).

## ImportError / нет crawl4ai

**Симптомы:**
```
ModuleNotFoundError: No module named 'crawl4ai'
```
или скрипт сам пишет в лог:
```
Не установлен crawl4ai: ...
Установи зависимости:
    pip install -U crawl4ai httpx
    python -m playwright install chromium
```

**Что делать:**
```bash
pip install -U crawl4ai httpx
python -m playwright install chromium
```

`playwright install chromium` обязателен — crawl4ai использует его как браузер
(даже хотя сам Chrome у пользователя установлен — playwright под собой держит
свою копию Chromium).

## Скрипт падает: CDP endpoint недоступен

**Симптом (exit code 4):**
```
CDP endpoint http://localhost:9222 не отвечает: ...
Не удалось подключиться к Chrome по CDP (...)
Скилл работает поверх ЖИВОГО Chrome пользователя — он должен быть
запущен с флагом `--remote-debugging-port=9222`.
```

**Причины и что делать:**

1. **Chrome закрыт** → запустить Chrome через ярлык с
   `--remote-debugging-port=9222` (см. SKILL.md → «Подготовка живого Chrome»).

2. **Chrome открыт, но без флага.** Chrome не активирует debug-порт, если
   уже есть процесс с тем же профилем без флага. Решение:
   - Закрыть **все** окна Chrome (включая фоновые — проверить трей).
   - Запустить Chrome через специальный ярлык с флагом.
   - `curl http://localhost:9222/json/version` должен ответить JSON.

3. **Порт 9222 занят другим процессом.** Передать другой порт:
   - В ярлыке Chrome: `--remote-debugging-port=9333`
   - В скилле: `--cdp-url http://localhost:9333`
   - Проверить занятость: `netstat -ano | findstr :9222`

## В `article.md` есть несколько блоков `# ` (несколько статей)

**Причина:** JS_CLEANUP не успел удалить подгруженные следующие статьи перед
тем, как crawl4ai снял HTML. Очень редкий случай, но возможен на медленном
интернете или при больших страницах.

**Что делать:**
- запустить скрипт ещё раз на этом URL — обычно помогает;
- если повторяется — открыть `article.html` и проверить, сколько там
  `<div class="article article_view">`;
- временно увеличить таймауты в `JS_CLEANUP` (поднять `setTimeout` после
  скролла с 500 до 1000 мс).

## Несколько профилей Chrome

Скилл подключается к тому профилю, под которым **сейчас запущен** Chrome
с дебаг-портом. Чтобы переключить профиль:

1. Закрыть весь Chrome.
2. Запустить Chrome с обоими флагами:
   ```
   "C:\Program Files\Google\Chrome\Application\chrome.exe" --remote-debugging-port=9222 --profile-directory="Profile 1"
   ```
   (вместо `Default` — `Profile 1`, `Profile 2` и т.д.; имена смотри в
   `C:\Users\<user>\AppData\Local\Google\Chrome\User Data\`).
3. Убедиться, что в этом профиле залогинен VK.

## Кириллица в выводе сломана (на Windows)

**Симптом:** в `extractor.log` или в консоли вместо русских букв `???` или `Р`.

**Причина:** Windows-консоль не в UTF-8 по умолчанию.

**Что делать:** запускать скрипт с переменной окружения:

```bash
set PYTHONIOENCODING=utf-8     # cmd.exe
$env:PYTHONIOENCODING="utf-8"  # PowerShell
```

В лог-файл всё пишется в UTF-8 в любом случае, проблема только в консольном выводе.
