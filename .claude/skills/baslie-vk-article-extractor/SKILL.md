# baslie-vk-article-extractor

Извлекает VK-статью через Crawl4AI, подключаясь к **живому Chrome**
пользователя по CDP (Chrome DevTools Protocol). Авторизация в VK берётся
из реальной сессии браузера — никаких ручных экспортов куков.

---

## Что делает

Берёт публичный URL VK-статьи → подключается по CDP к запущенному Chrome
пользователя → открывает новую вкладку с залогиненной сессией VK →
удаляет соседние подгруженные статьи (VK при скролле триггерит «следующую
статью») → вытаскивает заголовок, абзацы, подзаголовки, картинки с подписями,
ссылки, медиа, og-метаданные → скачивает все фото локально → сохраняет
full-page скриншот. Сам Chrome не закрывает.

---

## Подготовка живого Chrome (один раз)

Скилл работает поверх **уже запущенного** Chrome пользователя — он должен
слушать CDP на порту 9222. Сессия VK берётся из этого Chrome автоматически.

1. **Закрыть все окна обычного Chrome.** Chrome не активирует debug-порт,
   если уже есть процесс с тем же профилем без флага.
2. **Создать ярлык Chrome** с целью:

   ```
   "C:\Program Files\Google\Chrome\Application\chrome.exe" --remote-debugging-port=9222
   ```

   (или одноразово запустить Chrome из терминала с этим флагом).
3. Запустить Chrome через этот ярлык.
4. Убедиться, что в этом Chrome залогинен VK — открыть `https://vk.com/feed`,
   должна загрузиться лента, а не форма входа.
5. Дальше держать Chrome открытым. Скилл будет работать молча, пока
   сессия VK живая.

**Health-check** вручную:

```bash
curl http://localhost:9222/json/version
```

Должен вернуть JSON с полями `Browser` и `webSocketDebuggerUrl`. Если ответа
нет — Chrome либо был запущен без флага, либо порт занят. См.
`references/troubleshooting.md` → раздел про CDP.

## Запуск

Перед каждым прогоном проверь, что Chrome открыт и слушает CDP. Если нет —
покажи пользователю инструкцию из раздела «Подготовка живого Chrome» и
остановись.

Команда (PowerShell или bash):

```bash
PYTHONIOENCODING=utf-8 python .claude/skills/baslie-vk-article-extractor/scripts/extract_vk_article.py "URL1" "URL2" ...
```

Параметры (все опциональны, дефолты подобраны под расположение скилла):

| Флаг | По умолчанию | Зачем |
|---|---|---|
| `URL1 URL2 ...` | — | Один или несколько URL VK-статей через пробел (positional). |
| `--output-dir PATH` | `<project>/vk-articles` | Куда складывать результат. |
| `--cdp-url URL` | `http://localhost:9222` | CDP endpoint живого Chrome. |
| `--no-headless` | (не задан) | При CDP игнорируется — режим определяется живым Chrome. |

Скрипт:
- проверяет CDP endpoint (`/json/version`) и забирает куки из живого Chrome;
- запускает один Playwright-сеанс через CDP на весь батч;
- каждый URL → отдельная папка `<output-dir>/<slug>/`;
- ведёт общий лог `<output-dir>/extractor.log` + копию в каждой папке статьи;
- падает с понятным сообщением (exit 4), если CDP недоступен или не установлен `crawl4ai`.

### Если зависимости не установлены

Скрипт сам напишет в лог нужные команды:

```bash
pip install -U crawl4ai httpx
python -m playwright install chromium
```

`playwright install chromium` нужен для короткого CDP-коннекта, через
который скилл забирает куки из живого Chrome (для скачивания картинок
с правильным `Referer`).

## Что получится

Для каждого URL — папка `vk-articles/<slug>/`:

```
vk-articles/<автор>-<slug-статьи>/
├── article.md          ← основной markdown с иерархией (#, ##, маркированные списки)
├── article-fit.md      ← очищенная версия (если выдал crawl4ai)
├── article.html        ← cleaned HTML для отладки
├── metadata.json       ← og:title, og:description, og:image, og:url, ...
├── links.json          ← {"internal": [...], "external": [...]} полный
├── media.json          ← {"images": [...], "videos": [...], "audio": [...]}
├── images.json         ← маппинг URL → локальный путь / ошибки скачивания
├── summary.json        ← сводка (title, кол-во картинок/видео/ссылок, status_code)
├── screenshot.png      ← full-page PNG (для визуальной сверки)
├── extractor.log       ← копия общего лога на момент завершения этой статьи
└── images/
    ├── 001_<hash>.jpg
    ├── 002_<hash>.jpg
    └── ...
```

В корне `<output-dir>/` дополнительно:

- `extractor.log` — общий лог за весь прогон;
- `batch_summary.json` — список всех URL с их `summary` или ошибками.

`summary.json.title` берётся из `og:title` (стабильный), не из `<title>`
страницы (тот меняется при подгрузке VK следующих статей).

---

## Что Claude должен сделать после прогона

1. Прочитать `<output-dir>/batch_summary.json`. Если все URL завершились с
   `ok: true` — прогон успешен.
2. Для каждой успешной статьи прочитать `summary.json` и **первые ~30 строк**
   `article.md`. Сверить, что заголовок (первая строка с `# `) соответствует
   `summary.title`.
3. Кратко сообщить пользователю по каждой статье:
   - заголовок (`title`);
   - кол-во картинок (`images_downloaded` / `images_total`);
   - кол-во видео (`videos_total`);
   - количество ссылок (`internal_links` + `external_links`);
   - путь к папке.
4. **Флагнуть проблемы**, если выполняется любое из:
   - `status_code != 200`;
   - `images_total == 0` (вряд ли статья без фото — скорее login wall);
   - в `extractor.log` встречается «login» / «Войдите» / «UnauthAction»;
   - `images_downloaded < images_total` — посмотреть `images.json` на ошибки;
   - в `article.md` есть второй блок `^# ` после первой статьи (значит, JS_CLEANUP не отработал — редкий случай).

   В этих случаях предложить пользователю проверить:
   - Chrome запущен с `--remote-debugging-port=9222`;
   - в этом Chrome залогинен VK (`vk.com/feed` отдаёт ленту, не форму входа);
   - `curl http://localhost:9222/json/version` отвечает.

   Подробности — `references/troubleshooting.md`.

---

## Зависимости и обходы

Подробности по типичным ошибкам — в `references/troubleshooting.md`. Прочитай
его, если столкнулся с любым из:

- VK показывает форму логина / `status_code` редиректа;
- `images_total > 0`, но `images_downloaded < images_total` (VK CDN отвечает 403);
- видео в статье есть, а `videos_total == 0`;
- скрипт падает на ImportError;
- скрипт падает с exit 4 «CDP endpoint недоступен» (Chrome не запущен с дебаг-портом).

---

## Что НЕ делает скилл

- Не работает с постами на стене (`vk.com/wall...`) — другая структура DOM.
- Не парсит закрытые сообщества (нужен дополнительный логин).
- Не извлекает встроенные видео в полноценный `m3u8`/`mp4` — только URL iframe-источника.
- Не делает batch из файла-списка (если нужно много URL — передавать через xargs / shell-цикл).
- Не редактирует существующие папки `vk-articles/<slug>/` — при повторном
  прогоне на тот же URL содержимое перезаписывается.
